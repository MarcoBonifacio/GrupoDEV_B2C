INTRODUCCIÓN
--------------------------------------------------------------------------------
Este informe documenta el desarrollo completo del sistema "Leandro Baterías",
una plataforma e-commerce para la gestión de inventario y ventas de baterías
automotrices en Perú. El proyecto utiliza metodología Scrum y está diseñado
con arquitectura Clean Architecture.

================================================================================
1. ESTRUCTURA DEL PROYECTO
================================================================================

1.1 ARQUITECTURA GENERAL
--------------------------------------------------------------------------------
El sistema está diseñado con una arquitectura de 3 capas:

  PRESENTACIÓN (Frontend)
  ├── HTML5 + CSS3 + JavaScript (Vanilla)
  ├── index.html - index7.html (6 versiones evolutivas)
  └── js/, css/, assets/

  API (Backend - ASP.NET Core)
  ├── Controllers/
  ├── Services/
  └── Middleware/

  DATOS (SQL Server)
  ├── Tablas relacionales
  ├── Stored Procedures
  └── Seed Data

JUSTIFICACIÓN: Esta separación permite escalabilidad, mantenimiento sencillo
y seguridad en la manipulación de datos.

3.1 INTEGRACIÓN DE MEDIOS DE PAGO
--------------------------------------------------------------------------------

El sistema implementa 3 métodos de pago:

MÉTODO YAPE
  └── Número: 927 456 789
  └── Icono: https://upload.wikimedia.org/wikipedia/commons/0/08/Icono_de_la_aplicación_Yape.png
  └── Justificación: Método de pago más popular en Perú

MÉTODO PLIN
  └── Número: 927 456 789
  └── Icono: https://images.seeklogo.com/logo-png/38/1/plin-logo-png_seeklogo-386806.png
  └── Justificación: Segunda opción de pago móvil más usada

MÉTODO TARJETA
  └── Icono: https://www.footloose.pe/arquivos/ids/1369498/logos-de-bancos-min.jpg
  └── Campos: Número de tarjeta, MM/AA, CVV
  └── Justificación: Pago con tarjetas de crédito/débito

3.2 LÓGICA DE SELECCIÓN DE PAGO
--------------------------------------------------------------------------------

En index7.html, la función selectPayment() maneja:
  - Resaltado visual del método seleccionado
  - Mostrar/ocultar campos de tarjeta según selección
  - Persistencia de la selección en variable global

================================================================================
4. SISTEMA DE DOCUMENTACIÓN (FACTURAS, BOLETAS, COMPROBANTES)
================================================================================

4.1 TIPOS DE DOCUMENTO
--------------------------------------------------------------------------------

COMPROBANTE DE PAGO
  └── Código: NULL (sin documento fiscal)
  └── Campos requeridos: Ninguno (opcional dar DNI)
  └── Color en PDF: Azul (#1A73E8)
  └── Justificación: Para ventas sin necesidad de comprobante fiscal

BOLETA DE VENTA
  └── Código: 03
  └── Campos requeridos: DNI (8 dígitos)
  └── Color en PDF: Rojo (#B40000)
  └── Justificación: Comprobante para persona natural sin RUC

FACTURA ELECTRÓNICA
  └── Código: 01
  └── Campos requeridos: RUC (11 dígitos)
  └── Campos opcionales: Dirección fiscal
  └── Color en PDF: Verde (#006400)
  └── Justificación: Comprobante para empresas con RUC

4.2 GENERACIÓN DE PDF
--------------------------------------------------------------------------------

La función generatePDF() en index7.html:
  - Genera PDF dinámico según tipo de documento
  - Incluye: Fecha, hora, datos del cliente, items, totales
  - Diseño visual diferenciado por tipo
  - Nombre del archivo: COMPROBANTE_XXX.pdf, BOLETA_XXX.pdf, FACTURA_XXX.pdf

4.3 VALIDACIONES IMPLEMENTADAS
--------------------------------------------------------------------------------

  - Nombre/Razón Social: Requerido
  - Teléfono: 9 dígitos obligatorios
  - DNI (Boleta): Exactamente 8 dígitos
  - RUC (Factura): Exactamente 11 dígitos
  - Dirección: Solo para facturas (opcional)
  - N° Operación: Opcional para todos

5. BASE DE DATOS (SQL SERVER)
================================================================================

5.1 TABLAS IMPLEMENTADAS
--------------------------------------------------------------------------------

Marcas
  └── Campos: IdMarca, Nombre, Descripcion, LogoUrl, Activo
  └── Justificación: Categorización de baterías por marca

Baterias
  └── Campos: Id, IdMarca, IdCategoria, Codigo, Nombre, Voltaje, Amperaje,
             PotenciaArranque, Precio, PrecioCosto, StockActual, StockMinimo,
             ImagenUrl, GarantiaMeses, Destacado, Activo
  └── Justificación: Catálogo completo de productos

Categorias
  └── Campos: IdCategoria, Nombre, Descripcion, Activo
  └── Justificación: Clasificación técnica (Convencional, AGM, Gel, Premium)

Pedidos
  └── Campos: IdPedido, IdCliente, NumeroPedido, Estado, Total, TipoPago, etc.
  └── Justificación: Seguimiento de ventas

Pagos
  └── Campos: IdPago, IdPedido, TipoPago, Estado, NumeroOperacion
  └── Justificación: Registro de transacciones

Facturas
  └── Campos: IdFactura, NumeroFactura, Serie, TipoDocumento, etc.
  └── Justificación: Documentación fiscal

Transportistas
  └── Campos: IdTransportista, Nombre, RUC, Telefono
  └── Justificación: Logística de entregas
